# Pilot Operator Checklist

> **Status: blank draft checklist; no item is completed by publication.** Work
> from a private controlled copy. Do not tick this repository template or add
> names, dates, evidence, attestations, or private paths to it.

## A. Commission and prerequisites

- [ ] Confirm the controlling protocol decision and current
  `reader-evidence.json` state before doing study work.
- [ ] Confirm the Reader's Map, glossary, and accessible-navigation references
  exist at the exact tested commit.
- [ ] Build the exact versioned snapshot and its HTML, EPUB, and PDF artifacts.
- [ ] Validate headings, links, landmarks, reading order, text alternatives,
  extraction, zoom/reflow, keyboard access, and screen-reader use; retain the
  human screen-reader smoke-test record privately.
- [ ] Freeze a manifest of every tested artifact and SHA-256 digest.
- [ ] Appoint separate facilitator, coder A, coder B, adjudicator, and
  reviewer/custodian; record identities and conflict checks privately.
- [ ] Confirm the author holds none of those study roles.
- [ ] Obtain independent ethics/safety review where required or uncertain.
- [ ] Resolve recruitment jurisdiction, participant-facing consent, private
  retention/deletion, incident response, and payment handling.

## B. Finalise and freeze the pilot

- [ ] Replace every bracketed field in a private working packet.
- [ ] Freeze the exact protocol, instrument, rubric, sample rule, disclosures,
  ethics terms, provisional falsification rule, and synthetic control.
- [ ] Freeze the recruitment channels, eligibility screen, role assignments,
  living-wage source/rate, and participant-facing materials privately.
- [ ] Confirm the packet contains no severity label, core designation, release
  threshold, denominator, repetition unit, or real-reader verdict mapping.
- [ ] Construct the pre-registration payload with the exact fixed-protocol,
  prerequisite, predecessor-attempt, and prior-history-head bindings.
- [ ] Obtain the external freeze binding with the computed
  `attested_payload_sha256` and canonical UTC time.
- [ ] Materialise one frozen `not-run` pilot attempt in the sole machine source.
- [ ] Run the reader checker in structural and executable modes, the admission
  gate self-test, the full-society ledger check, quick verification, and full
  verification.
- [ ] Commit the frozen attempt before recruitment, invitation acceptance, or
  data collection.

## C. Recruit and compensate

- [ ] Use more than one recruitment channel and record decisions before seeing
  responses.
- [ ] Screen non-specialist eligibility and prior exposure privately.
- [ ] Seek varied reading confidence, language backgrounds, and accessibility
  needs without quotas or outcome weighting.
- [ ] Give accessible disclosures, time estimates, content warnings, privacy
  terms, withdrawal rights, and the compensation formula before consent.
- [ ] Supply the exact frozen snapshot in the participant's usable format.
- [ ] Keep a private live count of screened, enrolled, attempted, withdrawn,
  inadmissible, and admissible-completed records.
- [ ] Never replace a participant because of an answer.

## D. Run each remote moderated session

- [ ] Confirm snapshot identity, access, consent, and willingness to continue.
- [ ] Resolve access mechanics without explaining substantive content.
- [ ] Start the attempted-session count when the first unaided prompt is
  delivered.
- [ ] Ask all six ratified prompts exactly, in order, without content aid.
- [ ] Close the unaided section before diagnostic feedback.
- [ ] Record responses verbatim and record every facilitator, access,
  connection, consent, withdrawal, or protocol deviation immediately.
- [ ] Protect pauses, skipping, access requests, safety, and withdrawal without
  retaliation or a reason requirement.
- [ ] Pay all time already spent under the frozen formula, irrespective of
  completion or admissibility.
- [ ] Stop sessions at 10 admissible completions or 12 attempted sessions,
  whichever occurs first.

## E. Code, adjudicate, and test the control

- [ ] Give coders identical opaque records without identity or diagnostic
  feedback.
- [ ] Lock coder A and coder B records independently before either sees the
  other.
- [ ] Give the separate adjudicator only the locked records and frozen rubric.
- [ ] Record unresolved coding as unresolved; do not select the favourable code
  or change a boundary post hoc.
- [ ] Have the reviewer/custodian classify admissibility independently of
  content coding.
- [ ] Publish no content outcome for inadmissible or withdrawn sessions.
- [ ] Run the synthetic transcript through the same coding workflow and reveal
  its plant key only after coding/adjudication is locked.
- [ ] Observe and record exactly one control status: `watched-failing`,
  `failed-to-fail`, or `indeterminate`.
- [ ] Record exactly one study-freshness custody attestation once run evidence
  exists.

## F. Close or void the attempt

- [ ] Confirm the stop produced at least 8 admissible completions.
- [ ] Confirm every bound artifact stayed unchanged and every required custody
  link, deviation, role record, and chronology is complete.
- [ ] Confirm protocol validity and a `watched-failing` control before recording
  completion.
- [ ] If any completion condition fails, preserve and void the attempt with a
  coded reason; do not delete it or rewrite it as not run.
- [ ] For a void attempt, revise only in a new pre-registration and successor
  attempt with a newly recruited pilot sample.
- [ ] For a valid attempt, generate the completion receipt from exact artifacts
  and privacy-minimal coded records.
- [ ] Run all structural, executable, gate, ledger, quick, and full checks before
  committing the terminal transition.

## G. Freeze the post-pilot decision basis

- [ ] Strictly after completion, freeze the decision packet binding the pilot
  pre-registration, tested snapshot, coded evidence, exclusions,
  disagreements, deviations, revised instrument, and control transcript.
- [ ] Produce and bind a sensitivity brief comparing defensible rule choices
  without holdout evidence.
- [ ] Perform the two-person privacy review before any public commit or author
  hand-off.
- [ ] Verify that no identity, raw response, free text, consent, withdrawal,
  contact, demographic, accessibility, compensation, or local private path is
  public.
- [ ] State expressly that the pilot tests the instrument and supplies
  threshold-design evidence; it does not test release suitability.

## H. Author decision hand-off

- [ ] Present only the frozen decision packet and sensitivity brief, with their
  exact digests, to the author.
- [ ] Require an explicit choice for every eventual taxonomy, misconception,
  core-veto branch, repetition unit, denominator, threshold, evaluability, and
  missing/adjudication field; nothing defaults silently.
- [ ] Materialise and commit the complete rule as `candidate` before asking for
  ratification of its exact commit and digest.
- [ ] Confirm no holdout evidence exists or was inspected.
- [ ] Preserve the author's later answer verbatim in the controlling decision
  record and sole machine source.
- [ ] Do not freeze or run the holdout, close the author-gated TODO, upgrade
  FS-CLM-37, satisfy Gate C, or send any reader result into Nibli during this
  pilot hand-off.
