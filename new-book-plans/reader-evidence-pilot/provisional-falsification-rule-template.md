# Provisional Pilot Falsification Rule Public Minimum

> **Status: public template only; not a frozen rule or executed control.** The
> exact plant set, synthetic wording, private observation mappings, and answer
> key remain in a nonce-protected external preimage. This file contains no
> release severity taxonomy or threshold.

## 1. Object and boundary

The object under test is the exact frozen pilot instrument-and-codebook
workflow. A privately committed synthetic transcript deliberately misstates
ordinary constructive life, democratic and private choice, normal public
function, delivery and repair, the prisoner's role, and external/model limits.
Those named themes are the public falsification envelope, not an answer key.

The control is not a participant, sample member, session, or holdout. It is a
necessary instrument falsifier and never evidence that the book or instrument
works on real responses.

## 2. Minimum procedure

The private rule must bind the exact instrument, codebook, seeded preimage,
plant key, expected code mapping, and their digests before collection. Coder A
and coder B apply the unchanged workflow independently and lock their records;
the adjudicator applies the frozen codebook; the reviewer/custodian compares
the final record with the private key only afterward.

The public record carries the commitment and final control status, not the
preimage, exact seed text, answer key, or private code mappings.

## 3. Public status semantics

- `watched-failing` — final adjudicated coding detects every privately declared
  plant and the workflow refuses a pass-like interpretation.
- `failed-to-fail` — coding reaches a final state but misses a declared plant
  or permits a pass-like interpretation despite it.
- `indeterminate` — unresolved coding, changed artifacts, a broken commitment
  or blindness record, missing custody, or another protocol defect prevents a
  final comparison.

Unexpected additional observations cannot offset a missed plant. This is a
control rule only; it supplies no release threshold, denominator, severity,
core status, or real-reader verdict.

## 4. Consequence

Only `watched-failing` satisfies the pilot's seeded-control prerequisite. A
`failed-to-fail` or `indeterminate` outcome requires preservation and voiding
of the attempt, revision under a new commitment, and a newly pre-registered
successor pilot. It is never rewritten as `not-run`.

A watched-failing control does not make R6 available by itself, establish
FS-CLM-37, predict a holdout, validate the later release rule, or satisfy Gate
C.
